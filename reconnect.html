Connect or reconnect the assistant

This page is for Benemetry staff who are administrators of Benemetry's QuickBooks Online company. It describes how the Benemetry QuickBooks assistant ("Claude assistant") is authorised with Intuit. The exact commands are in Benemetry's internal runbook.

When you need this

  • The first time the tool is connected.
  • After the tool was disconnected in QuickBooks.
  • When the stored credentials have expired: Intuit retires a refresh token after 100 days without use, and in any case five years after it was issued.
  • After the app's client secret has been regenerated in the Intuit developer portal.

How it works

Intuit's sign-in flow requires the browser to come back to a registered HTTPS address after you approve the connection. For this tool that address is the callback page on this site, a page of plain text. The tool itself runs on your computer and cannot be reached from the internet, so the final step is done by hand: you carry the address of the callback page from the browser to the tool. The one-time authorisation code in that address is useless without the app's secret, which never leaves your computer, and it expires within minutes.

Before you start

The credential file ~/.qbo/production.env must exist on the computer that runs the tool and hold the app's client ID, client secret, callback address and environment. If it was deleted when the tool was retired, recreate it from the internal runbook first; the connection command cannot run without it. If the file still holds credentials from an earlier connection, expired or revoked, blank the two token lines, QUICKBOOKS_REFRESH_TOKEN and QUICKBOOKS_REALM_ID, immediately before running the command and without using the tool in between: with old values in place the command reports that re-authorisation is needed instead of starting one, and with blank values the tool itself would try to start a sign-in from inside the Claude application. The command fills the lines again when the connection succeeds.

Steps

  1. On the computer that runs the tool, run the connection command from the runbook (npm run auth in the server folder, pointed at the production credential file).
  2. The command prints an authorisation link, opens it in your browser and waits for the result on port 8000 of your computer.
  3. Sign in to Intuit, choose Benemetry Ltd's company and approve the connection.
  4. Intuit sends your browser to the callback page on this site. Its address now ends with ?code=…&state=…&realmId=…. The page does nothing with it.
  5. Copy the full address from the browser's address bar. Replace everything before the ? with http://localhost:8000/callback, keep everything from the ? onwards unchanged, and open the result in the same browser. Alternatively, from a second terminal on the same computer, fetch it with curl, with the address in quotes.
  6. The tool checks that the state value matches the one it issued, exchanges the code with Intuit and saves the new credentials in its file. The terminal prints a success message and the browser shows a "Successfully connected" page.

If something goes wrong

  • Intuit shows an error about the redirect URI. The callback address registered in the Intuit developer app does not match the address of the callback page exactly (scheme, host, path, no trailing slash). Fix the registration; nothing on this site needs to change.
  • The tool rejects the state, or the code has expired. Stop the command and start again from step 1. Codes are single-use and short-lived.
  • The browser shows "Processing…" instead of success. Browsers sometimes deliver the callback twice; the tool exchanges the code only once. Wait for the terminal.
